# Mobile Release Runbook (iOS & Android)

Operational guide for taking the Capacitor apps from a code change to the stores. Code-level setup (deep links, push scaffold, build matrix, assets) is already in the repo; this document covers the manual credential, console, and device-QA steps that only a human can do.

## 1. Build matrix

| Script | Vite mode | Env file |
| --- | --- | --- |
| `npm run build:cap:staging` | `capacitor-staging` | `.env.capacitor-staging` |
| `npm run build:cap:prod` | `capacitor-production` | `.env.capacitor-production` |

Both env files are committed placeholders — fill in `VITE_API_BASE` (deployed HTTPS API, no trailing slash) and the `VITE_SUPABASE_*` values per environment before building. They may only contain public client config. After building, open the IDE with `npm run cap:open:android` / `npm run cap:open:ios`.

## 2. OAuth deep links — one-time setup and device QA

Code side (done): native sign-in opens the system browser and returns via `com.carestickers.app://auth-callback` (`src/lib/native.ts`); the scheme is registered in `AndroidManifest.xml` and iOS `Info.plist`, and allow-listed in `supabase/config.toml`.

Manual steps:

- [ ] Add `com.carestickers.app://auth-callback` to the **hosted** Supabase dashboard (Auth > URL Configuration > Redirect URLs) — `config.toml` only covers the local stack.
- [ ] Google Cloud Console: create OAuth clients of type **iOS** and **Android** for the app identifiers if web-client sign-in is rejected on devices.
- [ ] Apple Developer: enable **Sign in with Apple** for the `com.carestickers.app` bundle ID.

Device QA (physical devices, staging build):

- [ ] Google sign-in on Android and iOS: system browser opens, returns to the app, session is live.
- [ ] Apple sign-in on iOS (required by App Review when other social logins are offered).
- [ ] Magic-link email opens the app when tapped on the device.

## 3. App icons & splash screens

Placeholder art lives in `assets/` (`icon-only.png`, `icon-foreground.png`, `icon-background.png`, `splash.png`, `splash-dark.png`), generated by `npm run assets:placeholders`. To ship final branding:

1. Replace the files in `assets/` with final art (icon 1024x1024, splash 2732x2732 centred logo).
2. Run `npm run assets:generate` (regenerates all Android mipmaps/drawables and iOS asset catalogues).
3. Rebuild (`npm run build:cap:prod`) and verify in both IDEs.

- [ ] Verify safe-area insets on notched devices (`viewport-fit=cover` + `.safe-top` helpers are already in the web code; check header/nav on an iPhone with a notch and an Android with a cutout).

## 4. Push notifications — credentials and native config

The scaffold is complete: `push_tokens` table (`supabase/migrations/0007_push_tokens.sql`), `POST /api/push/register`, an FCM HTTP v1 send pipeline (`server/src/push.ts`) that fires on new social interactions, and the client bridge (Settings toggle → native permission + token registration; taps open the Social tab). Sending stays a logged no-op until credentials exist.

Manual steps:

- [ ] Create a Firebase project and add Android app `com.carestickers.app`; download `google-services.json` into `android/app/` (gitignored; the Gradle plugin applies automatically when present).
- [ ] iOS: add the app in Firebase, upload your **APNs Auth Key** (Apple Developer > Keys) to Firebase Cloud Messaging settings, add `GoogleService-Info.plist` to the Xcode project, and enable the **Push Notifications** capability + **Background Modes > Remote notifications** in Signing & Capabilities.
- [ ] Server: set `FCM_SERVICE_ACCOUNT_JSON` (Firebase Project settings > Service accounts > Generate new private key, pasted as one line) in the API host environment.
- [ ] Apply the migration (`npm run db:push`) and regenerate types (`npm run db:types`).
- [ ] Device QA: enable notifications in Settings, send a high-five from another account, verify the notification arrives and tapping it opens the **Social** tab (cold start and backgrounded).

## 5. Store submission checklists

### Both stores

- [ ] Developer accounts: Apple Developer Program (paid, annual) and Google Play Console (one-time fee).
- [ ] Privacy policy URL: `https://<your-domain>/privacy.html` (served from `public/privacy.html`).
- [ ] Final icons/splash generated from real art (section 3).
- [ ] Production build via `npm run build:cap:prod` against the production API.

### App Store Connect (iOS)

- [ ] Bundle ID `com.carestickers.app` registered; Signing & Capabilities configured in Xcode.
- [ ] Archive and upload via Xcode Organizer.
- [ ] Listing: name, subtitle, description, keywords, screenshots (6.7" and 5.5" iPhone; iPad if supported).
- [ ] Privacy nutrition labels: declares account info (email), user content (goals/stickers), identifiers; no tracking.
- [ ] Review notes: provide a demo account (email + password) so App Review can sign in.
- [ ] Sign in with Apple offered alongside Google (guideline 4.8).
- [ ] TestFlight internal testing round before public release.

### Google Play Console (Android)

- [ ] Generate an upload key, configure **Play App Signing**, build a signed **AAB** in Android Studio.
- [ ] Listing: title, short/full description, screenshots, feature graphic.
- [ ] **Data safety** form: data collected (email, user content), encrypted in transit, account deletion path.
- [ ] Content rating questionnaire.
- [ ] Internal testing track rollout before production.

## 6. WebView behaviour QA (per release)

- [ ] **Offline**: airplane mode → app shell still opens (service-worker cache); actions fail gracefully with error toasts; recovery after reconnect without restart.
- [ ] **Session refresh**: leave the app installed >1 hour (access-token expiry), reopen, confirm supabase-js silently refreshes and no sign-out occurs.
- [ ] **Deep links** and **push taps** (sections 2 and 4) re-verified on release candidates.
